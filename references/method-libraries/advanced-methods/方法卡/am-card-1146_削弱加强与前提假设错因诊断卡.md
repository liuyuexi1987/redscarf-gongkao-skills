# 方法卡：削弱加强与前提假设错因诊断卡

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 削弱加强与前提假设错因诊断卡 |
| 适用题型 | 论点定位、论据关系、搭桥、拆桥、他因、因果倒置、必要前提 |
| 触发场景 | 用户做错该类题后，讲解/复盘结束，需要判断错因并写入错因卡或弱点档案时 |
| 步骤逻辑 | ① 先查论点是否找准（锚点）；② 再查选项作用位置（论点/论据/论证过程/他因）；③ 再查削弱力度排序和前提假设验证；④ 最后归因写入弱点档案 |
| 高频错因 | 论点没找准、削弱加强作用位置错、他因和解释说明搞混、因果倒置选项忽略、前提假设选了加强项、否定代入法没用 |
| confidence | high |
| 不适用条件 | 1. 资料分析模块中的论点理解题不在本卡诊断范围
| 反向触发 | 1. 用户做对削弱加强题后自行复核答案且无需诊断错因
2. 同一削弱加强题型连续答对多次无需诊断
3. 题目属于纯论据有效性判断题不涉及推理结构错因 |
2. 题干论点无法确定或存在多种合理解读时不做诊断
3. 纯翻译推理题（形式逻辑）由翻译推理诊断卡处理 |

## 诊断流程

### 第一步：查论点定位

- 论点是否找准？80% 在最后一句，关注"据此认为""因此""所以"等标志词。
- 是否把背景信息、论据、例子当成了论点？
- 论点关键词是否完整覆盖？选项是否只覆盖了论点的一部分？
- 用户是否从第一个字开始读文段，被背景信息干扰？

### 第二步：查选项作用位置

- 削弱/加强的是论点、论据、论证过程还是他因？
- 该拆桥（否定隐含前提）却找了他因？该补前提却补了无关信息？
- 归因题中：否定此因 vs 他因削弱 vs 因果倒置，力度排序是否正确？
- 对比实验题：是否回归分组检查了初始状态和对比维度？

### 第三步：查力度排序与前提验证

- 因果倒置 > 否定此因 > 他因削弱 > 类比质疑，用户是否选了力度最弱的？
- 绝对化表述题：一个反例就够削弱，是否觉得"太小了不敢选"？
- 前提假设题：是否用了否定代入法验证？选的是加强项还是必要前提？
- 搭桥题：论据和论点之间是否有概念跳跃？选项是否补了这个跳跃？

### 第四步：查问法方向与归因

- "最不能削弱"=找无关项或加强项，是否看反？
- "最不能支持"=找削弱项或无关项，是否看反？
- 归因到具体层：是论点定位、作用位置、力度排序还是前提验证？

## 错因分类表

| 错因类型 | 判定信号 | 典型表现 | 写入弱点档案的建议标签 |
|----------|----------|----------|------------------------|
| 论点没找准 | 削弱加强时作用到背景或例子 | 抓了材料现象，没抓作者结论 | 判断-削弱加强-论点定位错误 |
| 作用位置错 | 选项作用位置不对 | 该拆桥却找他因，该补前提却补无关信息 | 判断-削弱加强-作用方式错误 |
| 他因和解释搞混 | 把解释说明当成了他因削弱 | 解释说明是让矛盾说得通，他因是提供另一个原因 | 判断-削弱加强-他因解释混淆 |
| 因果倒置忽略 | 忽略了因果倒置选项，选了力度更弱的 | 因果倒置力度通常大于他因削弱 | 判断-削弱加强-因果倒置忽略 |
| 前提选了加强项 | 前提假设题选了支持项而非必要项 | 加强项只是有利信息，不一定是必要条件 | 判断-前提假设-加强前提混淆 |
| 否定代入法没用 | 没有验证选项是否为必要前提 | 否定选项后结论仍成立，说明不是必要前提 | 判断-前提假设-否定代入遗漏 |
| 反例力度低估 | 绝对化表述下觉得反例"太小"不敢选 | 绝对化表述只需一个反例就够削弱 | 判断-削弱加强-反例力度低估 |
| 反向问法看反 | "最不能削弱"选了最能削弱的 | 否定词被忽略 | 判断-削弱加强-反向问法看反 |
| 覆盖范围不全 | 选项只覆盖论点的一部分 | 论点含两个文化迁移，选项只解释了一个 | 判断-削弱加强-论点覆盖不全 |

## 写回建议

- `判断-削弱加强-论点定位错误`：选项只削弱了背景事实，没有削弱题干论点，论点没找准
- `判断-削弱加强-作用方式错误`：该拆桥（否定隐含前提）却找了他因，削弱位置不对
- `判断-前提假设-加强前提混淆`：前提假设题选了加强项（有利信息），不是必要条件
- `判断-削弱加强-因果倒置忽略`：因果倒置选项力度最强，但被忽略选了力度更弱的他因削弱

## 使用边界

1. 本卡只用于错因诊断，不替代具体解题方法卡（如 am-card-0157 加强削弱三步法与论点先行、am-card-0007 前提假设三种模式）。
2. 无官方/已核验答案的削弱加强题，不得硬判错因，只能写方法倾向或待核对。
3. 用户给出思路时优先对照用户思路归因；没给思路时只能做低置信诊断。
4. 客观题官方答案冲突时先走冲突复核流程，不立即写错因卡。
