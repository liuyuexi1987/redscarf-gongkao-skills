# 方法卡：断点搭桥法

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 断点搭桥法 |
| 适用题型 | 判断推理——前提假设类（"补充前提""必须为真"等问法） |
| 触发场景 | 论据与结论之间存在概念跳跃（断点），选项需要建立断点两端的联系 |
| 步骤逻辑 | ① 找到结论和论据，定位两者之间的概念断点；② 若断点明显，直接找搭桥选项（连接断点两端概念）；③ 若断点被题干进一步解释（如植物属性→没活性），需追踪到最底层断点再搭桥；④ 有断点必搭桥，没搭桥的选项一律排除 |
| 高频错因 | 没有准确识别断点位置，被论据中的中间概念干扰；有断点还纠结其他未搭桥选项 |
| confidence | high |

## 补充说明

"多层断点"场景：当断点被题干进一步解释时（如论据含"属性A→状态B"，结论含"结论C"，表层看似断点在"属性A"和"结论C"之间，实际最底层断点在"状态B"和"结论C"之间），需追踪到最底层断点再搭桥，而非在表层概念上搭桥。

推出链条中的断点搭桥：当题干呈现"条件→中间结论→最终结论"的推出链条时，写清每一步推出关系，找中间缺环即可定位断点。

核心识别：断点存在于论据概念与结论概念之间，无论链条多少层，搭桥选项必须连接最底层的两个断点概念。

## 不适用条件

- 论据与结论之间不存在概念跳跃（概念完全一致）时不适用。
- 题目问法为"削弱/质疑"而非"前提假设"时，搭桥不是正确答案类型。
- 题干自身已将断点解释闭环（无跳跃）时，无需搭桥。

## 反向触发

- 当题干无断点但存在因果方向漏洞时，应换用"修补漏洞"法。
- 当题干无断点且无漏洞但存在必要依赖时，应换用"必要条件"法。
- 当选项中没有连接最底层断点的项时，应回头核验断点层级追踪是否准确。
