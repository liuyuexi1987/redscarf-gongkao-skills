# 方法卡：定义判断要件拆解法

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 定义判断要件拆解法 |
| 适用题型 | 判断推理——定义判断 |
| 触发场景 | 题目给出一个概念的定义，要求选出符合/不符合该定义的选项 |
| 步骤逻辑 | ① 拆解定义的核心要件（主体、客体、条件、方式、目的、结果）；② 用符号标记每个要件（如①主体②条件③方式④目的）；③ 逐一对比选项是否满足所有要件；④ 缺少任何一个要件→排除；⑤ 如果多个选项都满足→选最全面的那个 |
| 高频错因 | ① 只看定义的大意，没有逐要件拆解，漏掉了关键限定条件；② 被选项的"表面相似"迷惑，没有核对具体要件；③ 过度解读定义中的某个词，添加了定义没有的限定 |
| confidence | high |

## 补充说明
定义判断的核心是"要件匹配"——不是看选项"像不像"定义，而是逐项核对是否满足定义的每一个要件。技巧：定义越长越要拆解，短定义可以整体理解。常见要件类型：主体（谁）、客体（对谁）、条件（在什么情况下）、方式（怎么做）、目的（为了什么）。

## 不适用条件

- 题干直接考查货币政策、财政政策、法律规定等已有事实知识，且没有先给新定义时，应走常识判断，不走定义要件拆解。
- 只有"题干先给出概念定义，再要求选案例"时才使用本卡。

## 反向触发

- 当多个选项似乎都满足全部要件时，应换用"最优匹配"思路：比较哪个选项覆盖的限定条件更全、更准确，而非停留在"满足/不满足"的二元判断。
- 当定义中出现"包括但不限于""等"这类开放性列举时，不能仅凭要件排除，应补一步语义核验，避免将符合开放性列举的选项误排。
- 当题干定义极短、要件难以拆解时，应改用整体语义理解或选项差异比较，而非强行套用要件拆解。
