# 方法卡：和数列识别法

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 和数列识别法 |
| 适用题型 | 数量关系——数字推理（和数列） |
| 触发场景 | 数字推理中数字较小，差值无规律，但三项之间有求和关系 |
| 步骤逻辑 | ① 差值、比值没有稳定规律时，尝试相邻两项求和得到后一项；② 将候选关系在后续各项连续验证，不只凭一组数字定规律；③ 相邻项做合不成立时，再看奇偶分组、固定常数修正或其他递推关系 |
| 高频错因 | ① 只想到等差/等比→忽略和数列；② 两项做合无规律→不尝试三项做合 |
| confidence | high |

## 补充说明
和数列的典型结构是“前两项之和等于后一项”。它是做差、做商无法解释数列时的一条递推路径，必须用多个相邻位置连续验证。

## 不适用条件
- 可用项太少，候选做合关系无法在后续位置重复验证时。
- 数列已呈现更直接的等差、等比、分组或倍数关系时，应先验证明显规律。
- 相邻两项求和只能解释个别位置、无法解释整个数列时。

## 反向触发
- 当相邻两项做合验证失败时，可再检查三项做合或奇偶分组做合；这些候选仍须在至少两个连续位置成立。
- 当数列呈比例增长特征时，应改用作商法或"等比修正与乘法递推法"。
- 当三项做合得到的结果与下一项呈固定差值时，应补充作差核验，避免误判为等差。

## 最终验证动作

1. 用求得的求和规律从首项逐项递推，确认每一项都与原数列完全吻合。
2. 推出目标项后与选项比对；若目标项与最近选项有固定差值，检查求和公式中是否有末项修正或常数项。
3. 对三项求和（如 a(n+3)=a(n)+a(n+1)+a(n+2)），必须验证求和关系在至少两个连续位置都成立，不能只验证末位。
