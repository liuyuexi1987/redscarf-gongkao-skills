# 行测复盘一体版

> 面向公务员考试行测的讲题、复盘、错因诊断、方法训练、题库和复习 Skill。

[![Latest Release](https://img.shields.io/github/v/release/liuyuexi1987/xingce-review-pro?label=release)](https://github.com/liuyuexi1987/xingce-review-pro/releases)
[![License](https://img.shields.io/badge/license-GPL--3.0-blue.svg)](LICENSE)

当前版本：**v1.4.2**

本项目只处理行测，不处理申论。覆盖言语理解、逻辑填空、资料分析、数量关系、判断推理和常识判断。

## 一、先用起来：你只需要这样发消息

把题目、截图或 PDF 发给 Skill，再在前面说明想怎么处理即可。

### 1. 直接看解法

适合已经知道答案，想快速弄懂方法：

```text
行测解答：
【资料分析】某市2023年生活垃圾清运量为120万吨，2024年为132万吨。
问：2024年比2023年增长约多少？A.8% B.10% C.12% D.20%
```

系统会直接讲解、给出明确答案，并说明方法和考场速度。

### 2. 做一次完整复盘

适合想找出自己为什么错：

```text
行测复盘：
【判断推理】……题目……
我选 A，请按 1.4 核验；如果判错，执行脚本回写。
```

标准复盘通常先问：

```text
你为什么这么选？又是怎么排除其他选项的？
```

你可以先说自己的思路，也可以直接回复“讲吧”。如果你明确要求直接核验，系统会进入核验流程。

### 3. 让系统考你

```text
考我：资料分析增长率
考我：判断推理定义判断
复习：我最近的言语理解弱点
错题复测：资料分析增长量与增长率混淆
```

考我和复习会调用已有题库、错因卡、弱点档案和复盘引擎；主动提问不等于答错，不会自动增加错误次数。

### 4. 导入题库

```text
把这张试卷加入题库，只做题目提取和核验，不要讲解。
把这组 PDF 导入题库。
```

题库导入只负责 OCR/提取、切题、答案识别、核验和结构化保存，不自动讲题，也不自动生成错因卡。

## 二、六类题型怎么用

| 模块 | 可以直接这样说 | 重点能力 |
| --- | --- | --- |
| 言语理解 | `行测解答：这道主旨题……` | 主旨、意图、细节、标题、排序、填句 |
| 逻辑填空 | `行测复盘：我选B，分析这三个空` | 语境、词义、搭配、感情色彩和轻重 |
| 资料分析 | `资料分析：这题能不能速算？` | 公式、估算、直除、比重、增长率和综合分析 |
| 数量关系 | `数量关系：给我最稳的考场解法` | 方程、代入、枚举、工程、行程、概率等 |
| 判断推理 | `判断推理：按要件拆解讲` | 定义、类比、逻辑判断、削弱加强、图形 |
| 常识判断 | `常识判断：核对这道法律题` | 法律、政治、经济、科技、历史、地理和时政 |

如果只发题、没有说明意图，系统会先问你是想存档、看解法还是复盘。

## 三、你会看到什么样的答案

普通讲解和复盘第二轮都会保留完整的教学结构：

1. 题型识别
2. 答案来源与结论
3. 当前题推理或计算过程
4. 用户答案处理（有答案时）
5. 方法讲解与速度评估
6. 易错点和复盘动作
7. 写回回执（只有实际写入时）

其中“方法讲解与速度评估”不会被省略，至少会说明：

- 为什么使用这个方法、具体怎么做、先看什么、何时停止；
- 预计用时、关键步骤数、模型推理风险、是否值得做；
- 本轮真实读取的方法卡或方法依据。

资料分析还会在正式计算前单独给出“速算判定”：`可快速定位`、`不宜粗估，需直除或精算` 或 `数据不足，待核验`。

## 四、答案核验和错题写回规则

写回脚本只负责落盘，不负责判断答案、不生成错因，也不替代教学推理。

只有同时满足以下条件，才会自动写入错因卡和弱点档案：

1. 你明确给出了自己的答案；
2. 题面和答案已经核验，且不存在答案冲突；
3. 系统确认你的答案错误；
4. 完整讲解正文已经完成。

因此：

- 普通讲题默认只讲不写；
- 答对只记录必要的学习结果，不生成错因卡；
- OCR 不清、题面不全或参考答案冲突时，停止写回并提示核对；
- 脚本不可用时才按 Markdown 协议降级；校验失败不能绕过安全门禁；
- 同一个 `event_id` 重复执行只返回 `noop`，不会重复增加错误次数。

成功写回后会返回机器可读回执，例如：

```json
{
  "status": "written",
  "event_id": "xingce-...",
  "state_root": "...",
  "files": ["错因卡/...", "弱点档案/..."],
  "warnings": []
}
```

## 五、为什么有时需要等一会儿

v1.4 保留了 1.3.1 的完整方法卡读取范围，不通过“快路径”或减少方法卡来换速度。这样做是为了避免出现“回答变短了，但关键方法、错因和选项核对也被省略”的问题。

目前的提速只发生在两个地方：

- 把互不依赖的协议和方法卡合并批量读取，减少工具往返；
- 完整讲解完成后，由 `writeback.py` 一次性完成多文件回写、幂等校验和事务回滚。

模型仍然需要完成题型识别、方法选择、独立复核、选项核对和完整输出。长链路、超过 60 秒或低置信 OCR 题，会明确说明“主要用于理解，考场不优先推荐”。

## 六、安装

### 方式 A：下载 Release

从 [v1.4.2 Release](https://github.com/liuyuexi1987/xingce-review-pro/releases/tag/v1.4.2) 下载：

```text
xingce-review-pro-v1.4.2.zip
```

解压后，Skill 目录应保持为：

```text
xingce-review-pro/
├── SKILL.md
├── agents/openai.yaml
├── scripts/writeback.py
└── references/
```

常见安装位置：

```text
Codex：    ~/.codex/skills/xingce-review-pro/
WorkBuddy：~/.workbuddy/skills/行测复盘一体版/
```

安装后重新打开或刷新会话，然后发送“行测解答”测试是否触发。

### 方式 B：开发者从仓库运行

```bash
git clone https://github.com/liuyuexi1987/xingce-review-pro.git
cd xingce-review-pro
```

运行时使用 `skills/xingce-review-pro/` 作为 Skill 源目录；维护工具和测试只在仓库根目录使用，不会被打进发布包。

## 七、开发者校验、测试和打包

在仓库根目录执行：

```bash
# 检查 Skill 结构、frontmatter、路径和脚本接口
python3 tools/validate_skill.py --skill-root skills/xingce-review-pro

# 检查方法卡、索引、引用、字段和置信度
python3 tools/audit_methods.py --skill-root skills/xingce-review-pro

# 运行行为、回写、幂等、回滚和故障测试
python3 -m unittest discover -s tests -v

# 生成确定性发布包和 SHA-256
python3 tools/package_skill.py --version v1.4.2
```

每次 push 或 Pull Request 都会触发 GitHub Actions；推送 `v*` 标签时会自动校验、打包并发布 Release。

发布包包含：

- `SKILL.md`、`agents/openai.yaml`、`references/`；
- 可运行的 `scripts/writeback.py`；
- `LICENSE` 和 `NOTICE`。

发布包不包含维护工具、测试文件、用户题库、错因卡、弱点档案和学习状态。

## 八、项目结构

```text
xingce-review-pro/
├── skills/xingce-review-pro/       # 可安装的行测 Skill
│   ├── SKILL.md                    # 路由、输出契约和安全门禁
│   ├── agents/openai.yaml          # UI 显示名和默认提示词
│   ├── scripts/writeback.py        # 结构化状态写回脚本
│   └── references/                 # 题型协议、方法库和复盘引擎协议
├── tools/                          # 仓库维护工具，不随 Skill 发布
├── tests/                          # 自动化测试
└── .github/workflows/              # CI 与 Release
```

方法卡是教学依据，写回脚本是状态落盘工具，两者职责分开：脚本不会降低方法卡读取范围，也不会参与解题。

## 九、常见问题

### 我只想知道答案，会不会自动写错题？

不会。直接使用“行测解答”，默认只讲不写。

### 我答错了但没有要求写回，会不会被记录？

只有明确答案、完成核验和完整讲解后才允许写回；没有满足门禁就不写错因卡和弱点档案。

### 资料分析截图数字识别错了怎么办？

系统会标注 OCR 置信度和误差边界。主体、年份、单位或选项无法核对时，不硬判答案，也不写错因。

### 能不能处理申论？

不能。本项目和当前 Skill 只处理行测；申论请使用独立的申论 Skill。
