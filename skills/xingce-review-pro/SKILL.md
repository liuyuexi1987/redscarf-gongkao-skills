# 行测复盘一体版 Skill v1.4.2

## 核心路由

1. 先做申论排除：出现“申论”、 “给定资料”、 “根据材料”、 “作答要求”、 “身份文种”、 “不超过XX字”等信号时停止本 Skill；本线程只提示“这条线程是行测专用”，不读取或修改申论技能。
2. `行测解答`直接进入【解法】；`行测复盘`进入【复盘】；`公考复盘`按明确意图兼容旧用户，无明确意图时按【解法】。
3. `考我`、`复习`、`错题复测`、`方法热身`、`学情报告`、`导出错题报告`读取复盘引擎；`导入/加入/收进题库`读取题库协议。
4. 只发题且没有意图时，只问：`这道题想怎么处理？①只存档 ②看解法 ③复盘（我先考你）`。

## v1.4 运行优化

正确性优先，不改变 1.3.1 的方法卡读取范围和先后顺序；提速只发生在工具编排与脚本写回。

1. 先读题型协议，并完整执行该协议规定的公式卡、高频卡、专题卡、综述和错因卡读取规则；不得以“快路径”“最小集合”或卡片数量限制删减方法依据。
2. 多个互不依赖的必读协议和方法卡在同一批次读取，减少模型与工具的串行往返；批量读取只改变调用方式，不改变读取内容。
3. 用户答案经复核判错并完成讲解后，读取 `references/review-engine/写回运行协议.md`，只调用一次 `scripts/writeback.py`。
4. OCR/图表、题面缺失、答案冲突、时效性事实或低置信判断仍按原协议读取全部必要资源，不因耗时跳过核验。
5. 运行时不得读取 `writeback.py` 源码、不得预扫描状态根、不得默认执行 `--dry-run`、不得在脚本成功后另写每日记忆；这些校验由脚本一次完成。
6. 运行优化不得省略审题、关键关系识别、公式/规则选择、选项核对、独立复核、资料分析速算判定、写回门禁或失败阻断。
7. 运行优化不是简答模式。用户可见回复仍执行对应题型的完整输出模板；不得合并或省略“方法讲解与速度评估”中的预计用时、关键步骤数、模型推理风险和是否值得做。
8. 错题写回是最后阶段：先完成并校验完整用户可见讲解，再调用写回脚本；脚本调用必须是本轮最后一个工具动作。讲解正文完成前不得生成写回 payload、调用脚本或显示任何落盘状态。

## 复盘首轮门禁

【复盘】第一轮只输出模式、题型、`你的答案 X：已记录，不判对错`，随后逐字输出：

`你为什么这么选这个答案，又是怎么排除其他选项的？`

`你也可以不答，直接说“讲吧”，我就开始讲解`

两句后立即停止：不读取方法库、历史状态，也不透露答案、公式、错因和选项提示。用户第二轮有任何回应即开始讲解，不要求完整回答。

## 判定与写回门禁

- 先读对应题型协议，再按协议导航读取方法卡；没有真实读取的卡号或文件名不得写入方法依据。
- 用户给出参考、粉笔、官方答案，或独立复核与给定答案冲突时，读取 `references/protocols/answer-authority.md`。
- 普通讲解默认只讲不写。只有用户明确给出答案且本轮已核验判错，才在完整讲解后写错因卡和弱点档案。
- 无答案、答案正确、答案冲突、OCR/题面未核验或主观题无官方答案时，不写错因卡和弱点档案。
- 客观题冲突时并列“我的复核”和“你给的答案”，暂停全部学习状态写回。
- 单题写回先读 `references/review-engine/写回运行协议.md` 并调用 `scripts/writeback.py`；脚本不可用时才读 `references/review-engine/复盘引擎说明.md` 手工 Markdown 写回。输入校验失败、状态根冲突或答案冲突不得降级绕过。
- `wrong_answer` 与 `review_result` payload 必须包含 `explanation_completed: true`；该字段只能在完整讲解正文已经完成后设置。脚本拒绝缺少该字段的状态写入。
- 用户可见的“已落盘”只能在脚本返回 `written` 或手工写入并确认文件存在后显示。

## 题型协议导航

| 题型 | 首读协议 |
|---|---|
| 主旨、意图、细节、结语、标题、排序、填句、阅读理解 | `references/protocols/verbal.md` |
| 逻辑填空、成语、实词、虚词、关联词、搭配 | `references/protocols/cloze.md` |
| 增长率、增长量、比重、平均数、倍数、基期、现期、资料分析 | `references/protocols/data.md` |
| 方程、枚举、代入、工程、行程、概率、排列组合、几何、数量关系 | `references/protocols/quant.md` |
| 法律、政治、经济、科技、历史人文、地理国情、时政、公文管理 | `references/protocols/common-sense.md` |
| 定义、类比、逻辑判断、削弱加强、图形推理 | `references/protocols/judgement.md` |
| 为什么错、错因卡、错因诊断、想太多、偷换、策略问题 | `references/protocols/error-diagnosis.md` |
| 方法库字段、索引、unit_id、schema | `references/protocols/method-router.md` |

常识与定义判断边界：已有法律、政策、经济、科技、历史等知识走常识判断；只有题干先给出新定义，再按要件匹配案例时才走定义判断。

## 方法库读取顺序

1. 先读题型协议中列出的 DataNotes 或 AdvancedMethods 必读卡。
2. 未命中再读 `references/method-libraries/advanced-methods/按题型索引/<模块>.md`。
3. 按题型协议继续读取 `references/method-libraries/综合方法库.md` 或对应专题综述作补充，不因已命中单卡而省略协议要求的综述。
4. DataNotes 只读 `references/method-libraries/data-notes/按题型索引.md` 和 `方法卡/`，不存在 `data-notes/资料分析.md`。
5. A/B 级卡可作依据，C 级只作检索线索，D 级跳过；方法依据必须写“方法论摘要 + 本轮真实读取的 card id/文件名”。
6. 逻辑填空遇词义、成语、搭配、轻重或感情色彩时，按 `references/lexical-discrimination/lexical-discrimination-guide.md` 读取命中词条；词义辨析与方法依据分开。
7. 卡片数量不是性能优化目标；题型协议列出的必读卡、配套卡和综述必须完整读取，可通过同批调用减少等待。

## 公共输出契约

普通解法或复盘第二轮至少包含：

1. 题型识别
2. 答案来源与结论
3. 当前题推理/计算过程
4. 用户答案处理（无用户答案时省略）
5. 方法讲解与速度评估
6. 易错点/复盘动作
7. 写回回执（仅实际写入后输出）

“方法讲解与速度评估”必须说明为什么用、怎么做、先看什么、何时停止、预计用时、关键步骤数、模型推理风险和是否值得做，并标出本轮真实方法卡。预计超过 60 秒、出现长链路、反复回溯或低置信识图时，明确写“本解法主要用于理解，考场不优先推荐”。

发送前逐项自检对应题型模板。运行优化不得导致标题合并、方法依据缺失、关键选项不解释或速度评估字段缩水；无用户答案和无实际写回时，只省略“用户答案处理”和“写回回执”，其余栏目保持完整。

普通讲解的最终草稿必须原样出现 `方法讲解与速度评估`、`预计用时`、`关键步骤数`、`模型推理风险`、`是否值得做`。`方法依据`不能替代该栏目；任一字段缺失都视为回复未完成，补齐后才能发送。

资料分析在正式计算前必须独立输出“速算判定”，标签只能是：`可快速定位`、`不宜粗估，需直除或精算`、`数据不足，待核验`。

## 题库与复盘引擎

- 题库导入只做提取/OCR、切题、答案识别、核验标记、结构化保存和导入报告，不讲解、不复盘、不写错因卡；读取 `references/protocols/question-bank.md`。
- 题库题只有题干/选项完整、答案明确、题答匹配且无提取疑点时，才能设为 `可自动判题: true` 和 `答案核验: 已核验`。
- 单题错题写回只读 `references/review-engine/写回运行协议.md`；考我、复习、掌握升级、画像刷新和导出读取 `references/review-engine/复盘引擎说明.md`。Skill 包只放模板，真实状态写入当前工作目录状态根。
- 状态事实以错因卡和弱点档案为准；主动提问主题与已验证弱点分开，不把主动提问次数计入错误次数。

## 维护边界

- 用户运行阶段优先纯文本；`scripts/writeback.py` 只执行已决定的结构化落盘，不判断答案、不生成错因、不改变方法选择。
- 用户可见回复不展示内部探索、文件读取、状态检查和 payload 构造过程，只展示讲解结果及真实回执。
- `tools/` 下的校验、审计和打包脚本只用于仓库维护，不随 Skill 包发布。
- 不在 Skill 包内存放用户题库、错因卡、弱点档案、学习记录、画像或导出报告。
