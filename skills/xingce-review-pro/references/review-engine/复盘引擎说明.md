# 复盘引擎说明

本文件是考我、复习、学情总结和错题报告的状态协议。单题写回命令、payload、回执与快路径以 `写回运行协议.md` 为唯一事实源。题型识别、复盘首轮门禁和讲解骨架由 `SKILL.md` 负责。

## 目录

1. 状态文件与路径
2. 考我与复习
3. 批改和写回
4. 掌握升级
5. 学情总结
6. 导出错题报告

## 状态文件与路径

| 层 | 文件 | 写入频率 | 用途 |
|---|---|---|---|
| 事实层 | `错因卡/` | 每道已核验错题 | 题面、答案、错因、方法依据、复习记录 |
| 实时索引 | `弱点档案/` | 每道已核验错题轻量更新 | 考我/复习优先读取 |
| 汇总视图 | `学习者画像.md` | 按需刷新 | 阶段性学情，不作实时事实源 |
| 正向层 | `reference/个人方法速查卡.md` | 达到掌握门槛后 | 已掌握方法 |
| 学习层 | `学习记录/` | 用户明确要求记录、有效理解或批量成绩 | 待巩固队列、正向理解、批改和阶段记录 |

### 解析候选路径

进入考我、复习、写回、学情总结或导出前，先用 `pwd` 确认当前工作目录，并只在该目录下列举候选族；路径解析不等于读取全部文件。

1. 标准运行态：`review-engine/弱点档案/`、`错因卡/`、`学习记录/`、`学习者画像.md`
2. WorkBuddy：`.workbuddy/memory/弱点档案/`、`错因卡/`、相关学习记录和 `学习者画像.md`
3. 旧运行态：`复盘引擎/弱点档案/`、`错因卡/`、`学习记录/`、`学习者画像.md`

以上路径都以 `pwd` 返回的**当前工作目录**为根。不得用 `find /Users`、从 `$HOME` 发起的 `**/` Glob 或其它全盘搜索，不得读取回收站、其它项目、skill 安装包模板或历史测试目录中的状态文件。

写回时优先使用当前工作目录中已存在且可写的运行态；都不存在则新建 `<pwd>/复盘引擎/`。**skill 安装目录只放发布模板，永远不是用户状态目录**：禁止向 `~/.claude/skills/`、`~/.workbuddy/skills/` 或本包 `references/review-engine/` 写错因卡、弱点档案、学习记录和导出报告。仅在当前工作目录只读、写入失败或多个本地目标确实无法判断时询问用户。缺少 `个人方法速查卡.md` 不代表没有学习状态。

选定状态根目录后，所有文件必须写在该根目录的固定子目录：`<状态根>/错因卡/`、`<状态根>/弱点档案/`、`<状态根>/学习记录/`、`<状态根>/导出/`、`<状态根>/reference/`。不得直接在 `<pwd>` 下新建裸 `错因卡/`、`弱点档案/` 或 `学习记录/`。

### 按场景最小读取

- 普通考我/复习：读非模板 `弱点档案/*.md`；若存在，再读单个 `学习记录/待巩固队列.md`，不扫描其它学习记录。
- 错题复测：再读到期错因卡的元数据和必要题面。
- 题库测验：再读已核验且可自动判题的必要题块。
- 学情总结/导出：读弱点档案、错因卡、学习记录；画像只作摘要和过期判断。
- 单题复盘首轮、普通解法、存档前：不预读历史状态；讲解完成后才按结果写回。

## 考我与复习

### 模式

| 触发词 | 行为 |
|---|---|
| `考我` / `复习` | 取最高优先级 1 题 |
| `考我 3 题` / `再考我一轮` | 从不同弱点或不同已核验题取 3 题，不足不凑数 |
| `错题复测` | 优先复测到期错因卡原题 |
| `方法热身：<模块>` | 从方法卡出 1–3 道方法工作流题 |
| `题库测验` | 只用用户导入、已核验且可自动判题的题 |

### 取题优先级

1. 到期错因卡：复测前先识别题型并检查必要题面。图推、空间图形和图形选项不从错因卡/题库自动复测原题，改考关联方法；用户本轮重新上传完整原图时，按新一轮讲解/复盘处理。资料分析只有在文字或 Markdown 表格已完整、可核验地还原全部数据、标签、图例、年份、单位、题干和选项时才复测原题；任一必要信息缺失、未识别或用问号/占位符表示时，跳过并取下一题，无替代题时改考关联方法。其余题型仅在题面完整且答案已核验时遮答案复测；不得把残缺题面包装成原题或方法自测题。
2. 用户题库：仅 `可自动判题: true` 且 `答案核验: 已核验` 的题。
3. 弱点档案方法工作流题：只问公式/方法选择、触发词、陷阱预判或上次错因归因。
4. 待巩固队列：选择状态为“待巩固”的主动提问主题，逐字输出该行已经保存的“下次复习问法”，再写“请直接回答。”并停止；不临场改写或补充数字、材料、选项、提示和答案，不把它称为错题或弱点。
5. 用户指定模块的方法热身：从方法卡的触发场景、步骤逻辑和高频错因出题。
6. 冷启动：以上均无时不编题，输出：`现在还没有可考材料。①拍一道你最近的错题 ②导入你自己的题库/答案页 ③或选一个题型，我用方法卡给你出 3 道方法工作流题热身。`

### 考我快路径

1. 实际读取至少一个非模板、非空弱点档案后，才能输出：`已读到你最近弱点：<key>（错 N 次），本次按【难度档 X】考你`。`key`、次数和难度必须逐字来自文件。
2. 没有真实弱点但读到待巩固队列时，输出：`已读到你最近主动学习的主题：<主题键>，这次先做一次方法复习。`；不得写“错 N 次”或称为弱点。
3. 两者都没有时，列出检查过的候选路径及“未读到/空模板”，然后走冷启动；不虚构弱点、主题或次数。
4. 有可用主题时在 10 行内出题，并标注：`非真题 · 方法自测 · 不计真题正确率`。
5. 方法工作流题不得编数值、年份、企业/GDP材料、四选一计算题或需要具体计算结果的仿真题。
6. 用户回答后再读对应方法卡或错因卡批改。

## 批改和写回

### 写回前置

- 先完成讲解，写回永远放在最后；不得用“已落盘”替代讲解。
- 单题错题写回只读 `写回运行协议.md`；考我批改、掌握升级、画像刷新和导出才读取本协议的对应章节。用户可见答复仍按“完整讲解 -> 写回回执”排序。
- 用户提供参考/粉笔/官方答案，或独立复核出现冲突时，才读 `references/protocols/answer-authority.md`；客观题答案冲突未解决时不写任何学习状态。
- 文件名中的日期使用当前系统日期，不使用题目材料年份；无法确认日期时省略日期，不猜测。
- 方法依据只引用本轮真实读取过的卡号或文件名。

### 脚本优先写回

执行命令、payload 字段、状态解析、回执处理、幂等和失败降级统一读取 `写回运行协议.md`。运行时不得读取脚本源码、预扫描状态根或默认执行 dry-run。

### 结果分流

| 结果 | 写回动作 |
|---|---|
| 已核验且用户答错 | 新建错因卡，增量更新弱点档案；不逐题刷新画像 |
| 已核验且用户答对 | 不写错因卡；仅用户明确要求记录或形成阶段记录时写学习记录 |
| 主观题无官方答案 | 只写待核对题面候选/学习记录，不计弱点 |
| 题面或答案不完整 | 只存待核对记录 |
| 客观题答案冲突 | 不写错因卡、弱点档案、学习记录或练习记录 |
| 用户主动提问但未判错 | 默认不写；仅用户明确要求记录时新建或合并 `学习记录/待巩固队列.md` |

“有效理解”必须有用户侧证据：用户亲自复述关键步骤/错因、在相关追问或考我中答对，或明确确认已经理解。仅模型完成讲解、用户只提交选项、只说“讲解/讲吧”或未回应，不算形成有效理解，不写学习记录。

### 主动提问队列

- 用户针对具体行测题、考点或方法要求讲解/复盘，不自动进入学习记录；只有用户明确说“记录/记入待巩固/以后考我这个”时，才更新 `学习记录/待巩固队列.md`。单纯题库导入、只存档、文件管理和产品咨询不入队。
- 队列按 `模块-题型-核心考点` 合并；重复提问只增加求助次数和最近日期，不重复建行。记录状态、用户表现（未作答/有思路/已答）和一条以 `【开放题，无选项】` 开头的纯概念“下次复习问法”，不保存未经核验的对错结论。问法只问方法选择、触发词、陷阱或关键步骤，不含新编数字、材料和选项。
- 同题已形成已核验错因时，以错因卡和弱点档案为准，队列同主题标记“转弱点”；用户展示有效理解时标记“已理解”。两种状态都不再参与普通考我取题。
- 队列复习答错或不会，只更新“复习未通过/仍待巩固”，不得增加真题错误次数；只有已核验原题答错才能进入弱点档案。

讲解模式按结果条件写回；默认不反问“要不要保存”，只有用户明确要求记录时才写入学习记录。

### 错题写回顺序

1. 新建 `错因卡/YYYY-MM-DD-模块-题型-短标题.md`，记录题面、用户答案、已核验答案、具体错因、方法依据和下次复习点。
2. 按 `模块-题型-核心考点` 定位弱点档案；新建前检索近义 key，命中则合并并记录别名。更新时只增量修改次数、难度档、掌握判定、下次出题策略和“每次错法”。
3. 普通错题不另写学习记录；用户答对且满足上述“有效理解”证据门槛、考我批改或多题批量判分时才写。
4. 最终确认错因卡和弱点档案真实存在；失败时报告具体路径和原因。

### 考我批改

- 来源为弱点档案时，更新对应弱点的复习记录、掌握度、难度档和下次出题策略；来源为待巩固队列时，只更新队列状态和复习结果。
- 能定位原错因卡时追加复习记录；不能定位时明确写“未定位到原错因卡，已写弱点档案”。
- 多题结果以当前批次精确分数 `x/y` 为唯一来源；百分比必须由该分数换算，不确定时不写百分比。
- 回执只列实际写入类型：`已落盘：<类型>`；失败项附路径和原因。

### 画像刷新

只在以下情况从错因卡、弱点档案和待巩固队列集中刷新 `学习者画像.md`：用户要求学情/错题总结；新增 3–5 张错因卡；一轮复盘或一套题结束；考我前发现画像过期。画像必须把“已验证弱点”“近期主动学习主题”“已掌握方法”分开，不把主动提问写成答错。未刷新时不得声称画像已包含最新状态。

## 掌握升级

满足任一条件才可把方法写入 `reference/个人方法速查卡.md`：

1. 用户答对且能复述关键步骤。
2. 同一聚合 key 连续答对两次。

未满足时最多标为“巩固中”。升级为“已掌握”后同步：弱点档案改为已掌握；画像对应项改为已掌握/抽查巩固；个人方法速查卡追加“方法名—一句话要点—来源卡”。三处不一致时继续修正，不先声称完成。

## 学情总结

触发：错题总结、学情报告、我现在哪儿弱、该练什么、下步建议、提醒复习等。

1. 按最小读取规则读取真实状态；没有非空状态时输出：`还没有错题记录，先复盘几道题或拍一套卷子进来，再来看总结。`
2. 数字和条目只来自文件，分开输出已验证弱点、近期主动学习主题和已掌握项；主动提问次数不得并入错误次数。
3. 给 2–3 条具体建议：练哪个考点、用考我/同类题/方法卡中的哪种方式。
4. 默认只读不写；用户明确要求阶段快照时才写入学习记录。

## 导出错题报告

触发：导出错题报告、导出错因报告、整理错题本、生成错因报告等。

1. 优先检查当前运行态的 `错因卡/*.md` 和 `弱点档案/*.md`，再检查其它候选路径。没有非模板错因卡时输出：`还没有可导出的错因卡，先复盘几道题再导出。`
2. 只整理已保存字段，不重新解题；缺失字段写“未记录”，不补编题干、解析、答案或方法依据。
3. 报告固定包含：导出摘要、错题清单、高频错因统计、复习建议和数据来源路径。
4. 默认写入当前运行态 `导出/错题报告-YYYY-MM-DD.md`，不再询问是否保存；路径只读或不明确时才在聊天中输出 Markdown。
5. 导出是只读整理，不新增错因卡、不改变弱点次数、不刷新画像。

## 维护约束

- 运行目录只放模板和用户状态，不放示例假数据。
- 用户可见讲解只在聊天中输出；不得为组织回答新建“讲解输出缓存/临时讲解/回答草稿”等 Markdown 文件。
- 运行时状态仍以 Markdown 为事实格式；脚本只负责安全、幂等和批量落盘，不替代讲解与裁决。
- 状态事实以错因卡和弱点档案为准，画像只作汇总。
