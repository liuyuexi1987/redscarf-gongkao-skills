# 公考复盘错因诊断 Skill

本文件只规定错因诊断内容和输出结构。意图门禁以 `SKILL.md` 为准；答案来源需要裁决时读 `references/protocols/answer-authority.md`；单题错因写回读 `references/review-engine/写回运行协议.md`，考我、复习和掌握升级读 `references/review-engine/复盘引擎说明.md`。

## 强制模式确认

每次触发本 skill，回答开头必须先写：

```text
已进入 xingce-review-error-diagnosis · 错因诊断模式。
```

## 强制回答协议

- 必须按“输出模板”或“错因卡输出模板”完整输出，不得缺项。
- 用户以“我不懂/分不清/有什么区别/帮我讲讲”等方式主动求助具体考点或方法时，按【解法】讲解，不自动写入待巩固队列；只有用户明确要求记录时才写入。
- 用户答案能否判错、后补答案和冲突修正统一按 `references/protocols/answer-authority.md`；未核验主观题不得生成错因。
- 错因必须落到“表现、原因、修正策略”，不得只写“粗心”“想太多”这类空标签。
- 如果方法库没有直接命中的同构 `source anchor（card id/文件名）`，必须写：`方法库无直接同构案例，以下主要是模型按公考复盘框架做的当前题诊断。`
- 截图 OCR 可作为题面候选；若有“题面截图与讲解不匹配/疑似截偏”警告，先用题干关键词、选项、讲解主题和用户提供信息交叉核对，大体吻合时可低/中置信使用。
- 诊断完成后仅在满足写回条件时按 `references/review-engine/写回运行协议.md` 调用一次脚本。

## 使用流程

1. 先读 `references/method-libraries/xingce-review/错因诊断.md`。
2. 若用户要案例或证据，再读 `references/method-libraries/xingce-review/按错因查案例.md`。
3. 输出错因时固定包含：表现、原因、修正策略。
4. 可附 1-3 个方法库相似依据摘要 + source anchor，但不要贴原文。

## 诊断边界

- 不把“不会”简单归因成粗心；要看定位、关系、词义、计算、策略哪个环节断了。
- 用户材料不足时，给低置信诊断并说明还需要哪类信息。
- 使用 OCR 题面候选时，必须说明“题面据 OCR，已按讲解关键词核对/仍需人工核对”。
- 如果方法库没有直接命中的同构 `source anchor（card id/文件名）`，必须明确写”方法库无直接同构案例，以下主要是模型按公考复盘框架做的当前题诊断”。
- 不要为了给标签而给标签；像“偷换概念”“想太多”“策略问题”这类归因，只有在方法证据或当前题表现足够清楚时才下结论。

## 常用问法

- “我这题选错了，按公考复盘错因帮我诊断。”
- “这次练习卷言语错很多，是想太多还是定位问题？”
- “把这道资料分析错题整理成错因卡。”

## 输出模板

1. 错因结论：<主要错因家族 + 置信度>
2. 表现：<题面/选项/计算/策略上具体错在哪里>
3. 原因：<定位、关系、词义、计算、策略哪一环断了>
4. 修正策略：<下次遇同类题的固定动作>
5. 方法依据：<依据摘要 + source anchor（card id/文件名）；没有时明确写”方法库无直接同构案例”>
6. 需要补充：<材料不足时列出还缺什么>

## 错因卡输出模板

- 题目：<模块/题型，如 言语·结语题>
- 我的选择 / 正确答案：<X -> Y>
- 错误环节：□定位 □关系 □词义 □计算 □策略
- 表现：<一句话说明 what went wrong>
- 错因家族：<过度思考/偷换/细节误读/逻辑误判/计算估算失误/策略问题>
- 方法依据：<依据摘要 + source anchor（card id/文件名）；无同构证据时明确写“方法库无直接同构案例”>
- 修正策略：<下次遇同类题的固定动作>
- 关联弱点档案：<模块-题型-核心考点，取规范名；链接到 review-engine/弱点档案/>
- 置信度：<高/中/低；材料不足时给低并说明缺口>

## 状态处理

单题错因按 `references/review-engine/写回运行协议.md` 写回；考我、复习、批量结果分流和掌握升级才读取 `references/review-engine/复盘引擎说明.md`。本文件不重复维护状态规则。
