# 方法卡：定义判断错因诊断卡

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 定义判断错因诊断卡 |
| 适用题型 | 单定义、多定义、主体、对象、目的、方式、结果、否定式问法 |
| 触发场景 | 用户做错该类题后，讲解/复盘结束，需要判断错因并写入错因卡或弱点档案时 |
| 步骤逻辑 | ① 先查要件拆解是否完整（主体、客体、条件、方式、目的、结果）；② 再查选项核对是否逐要件比对；③ 再查问法方向（符合/不符合、属于/不属于）；④ 最后归因写入弱点档案 |
| 高频错因 | 要件漏看、关键词替换、范围扩大/缩小、否定式问法看反、多定义混淆、概念名称信息忽略 |
| confidence | high |
| 不适用条件 | 1. 资料分析模块中的定义理解题不在本卡诊断范围
| 反向触发 | 1. 用户做对定义判断题后自行复核答案且无需诊断错因
2. 同一定义判断题型连续答对多次无需诊断
3. 题目属于日常逻辑理解题（如问成语含义）不属于定义判断范围 |
2. 定义本身含糊或存在歧义无法明确拆解要件时不做诊断
3. 用户已自行复核正确答案且无错因可诊断时不停留 |

## 诊断流程

### 第一步：查要件拆解

- 定义是否拆解了所有要件？主体（谁）、客体（对谁）、条件（什么情况下）、方式（怎么做）、目的（为了什么）、结果（达到什么效果）。
- 是否只看了定义大意而没有逐要件拆解？
- 定义越长越要拆解，短定义可以整体理解——用户是否对长定义偷懒没拆？

### 第二步：查选项核对

- 是否逐要件比对选项？还是只看选项"像不像"定义？
- 用户选项缺了哪个要件？是主体不对、目的不对、方式不对还是结果不对？
- 是否被选项的"表面相似"迷惑，没有核对具体要件？
- 是否过度解读了定义中的某个词，添加了定义没有的限定？

### 第三步：查问法方向

- 问的是"符合"还是"不符合"？"属于"还是"不属于"？
- 否定式问法是否看反？（问"不属于"却选了"属于"的选项）
- 多定义题：是否搞混了两个定义的不同要求？是否先找相同点再找不同点？

### 第四步：查概念名称与归因

- 概念名称本身是否包含关键信息？（如"互益素"→互+益→互相有益）
- 是否跳过概念名称直接读长解释？
- 归因到具体层：是要件漏看、关键词替换、问法方向还是多定义混淆？

## 错因分类表

| 错因类型 | 判定信号 | 典型表现 | 写入弱点档案的建议标签 |
|----------|----------|----------|------------------------|
| 要件漏看 | 正确项满足全部要件，用户项缺一个关键要件 | 漏掉主体、目的、方式、条件、结果中的某一个 | 判断-定义判断-要件漏看 |
| 关键词替换 | 用户项看似相近但替换了核心概念 | 把"主动"换成"被动"，把"公共"换成"私人" | 判断-定义判断-关键词替换 |
| 范围扩大/缩小 | 用户项超出或缩窄定义边界 | 把特定场景泛化到所有场景，或把一般情况限定为特殊 | 判断-定义判断-范围误判 |
| 否定式问法看反 | 问"不属于"却选了"属于"的选项 | 审题时没注意否定词，选了最符合定义的选项 | 判断-定义判断-否定问法看反 |
| 多定义混淆 | 两个定义的要求搞混 | 把 A 定义的条件用到了 B 定义上 | 判断-定义判断-多定义混淆 |
| 概念名称忽略 | 跳过概念名称直接读解释 | 概念名称中的关键信息（如"互""竞"）被忽略 | 判断-定义判断-概念名称信息遗漏 |
| 表面相似迷惑 | 选项和定义表面像但核心要件不匹配 | 选了一个"感觉像"但缺了关键要件的选项 | 判断-定义判断-表面相似误选 |
| 过度解读 | 添加了定义没有的限定条件 | 把定义中的"可以"理解成"必须" | 判断-定义判断-过度解读 |

## 写回建议

- `判断-定义判断-要件漏看`：选项缺少定义中的目的要件，只满足行为表面，没有逐要件核对
- `判断-定义判断-否定问法看反`：题干问"不属于"，选了最符合定义的选项，审题时否定词被忽略
- `判断-定义判断-关键词替换`：选项把定义中的"主动"替换为"被动"，看似相近但核心概念不同
- `判断-定义判断-多定义混淆`：两个定义的区分点没找对，把 A 定义的条件套到了 B 定义上

## 使用边界

1. 本卡只用于错因诊断，不替代具体解题方法卡（如 am-card-0974 定义判断要件拆解法、am-card-1000 定义判断字面拆解法）。
2. 无官方/已核验答案的定义判断题，不得硬判错因，只能写方法倾向或待核对。
3. 用户给出思路时优先对照用户思路归因；没给思路时只能做低置信诊断。
4. 客观题官方答案冲突时先走冲突复核流程，不立即写错因卡。
