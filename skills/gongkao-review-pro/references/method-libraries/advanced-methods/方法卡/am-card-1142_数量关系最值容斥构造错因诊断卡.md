## 诊断流程

### 第一步：查问法方向

- 问"至少…最多"还是"最多…至少"？方向有没有搞反？
- "至少需要几个保证…"是最不利原则题，有没有用反向构造的方法？
- "最多可能…"是构造最大值，有没有误用平均分配？

### 第二步：查构造方向与约束

- 求最大值 → 让其他项尽量小；求最小值 → 让其他项尽量大。口诀："求最少让别人最多，求最多让别人最少"。
- 构造时是否满足所有约束条件？"互不相同""每人至少 1 个""不能重复"等有没有遗漏？
- 构造完是否验证结果是否真的满足所有条件？
- 极端分配时，是否把余数正确处理（多分给某一项）？

### 第三步：查容斥与集合

- 二集合容斥：A∪B = A + B - A∩B，有没有忘记减交集？
- 三集合容斥：有没有正确使用公式？有没有漏掉两两交集或三集合交集？
- "只满足 A"= A - A∩B - A∩C + A∩B∩C（三集合），有没有算错？
- 交集上下限：下限 = A + B - 总数（若为负则为 0），上限 = min(A, B)，有没有搞反？

### 第四步：查验证与归因

- 构造结果代回验证：是否满足"互不相同""至少""至多"等所有条件？
- 容斥结果代回验证：各部分之和是否等于总数？
- 归因到具体层：是问法方向、构造方向、约束遗漏还是容斥公式？

## 错因分类表

| 错因类型 | 判定信号 | 典型表现 | 写入弱点档案的建议标签 |
|----------|----------|----------|------------------------|
| 至少至多方向搞反 | 问"至少"用了最大化思路 | 问至少分几个，却让其他人分得最少 | 数量-最值-至少至多方向搞反 |
| 构造忽略约束 | 构造结果不满足"互不相同"等条件 | 分配方案中有两人分到相同数量，违反条件 | 数量-最值-构造约束遗漏 |
| 验证遗漏 | 构造完没有回代检查所有条件 | 结果看起来对但实际不满足某个约束 | 数量-最值-验证步骤遗漏 |
| 二集合容斥公式错 | A∪B = A + B - A∩B 中忘记减交集 | 结果偏大（多算了交集部分） | 数量-容斥-二集合公式错误 |
| 三集合容斥公式错 | 三集合公式中漏掉两两交集或三集合交集 | 结果偏大或偏小 | 数量-容斥-三集合公式错误 |
| 交集上下限搞反 | 上限和下限的公式搞混 | 算出的区间不合理 | 数量-容斥-交集上下限混淆 |
| 只满足A算错 | "只满足A"漏掉了应减去的交集 | 结果偏大 | 数量-容斥-只满足条件计算错误 |
| 极端分配余数错 | 余数没有正确加到某一项上 | 总数不守恒或极端值不够极端 | 数量-最值-极端分配余数错误 |

## 写回建议

- `数量-最值-至少至多方向搞反`：求最少时应让其他人最多，方向搞反导致结果偏差
- `数量-最值-构造约束遗漏`：构造极端分配时忽略了"互不相同"等约束条件，导致方案不合法
- `数量-容斥-二集合公式错误`：二集合容斥必须减去交集，忘记减导致结果偏大
- `数量-容斥-交集上下限混淆`：交集上限 = min(A,B)，下限 = A+B-总数，搞反导致区间错误

## 使用边界

1. 本卡只用于错因诊断，不替代具体解题方法卡（如 am-card-0975 最值问题构造法、am-card-0386 容斥上下限公式）。
2. 容斥问题变体多，本卡聚焦常见二集合/三集合，不覆盖复杂多集合。
3. 用户给出思路时优先对照用户思路归因；没给思路时只能做低置信诊断。
4. 客观题官方答案冲突时先走冲突复核流程，不立即写错因卡。
