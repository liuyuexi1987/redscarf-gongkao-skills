# 方法卡：分步相乘——完成一件事的各步骤方案数相乘

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 分步相乘——完成一件事的各步骤方案数相乘 |
| 适用题型 | 完成一件事需要多个步骤，每步缺一不可 |
| 触发场景 | 题目说"先做A再做B"，需要多步才能完成 |
| 步骤逻辑 | 1. 把完成一件事分为若干步骤（每步都是必要的）；2. 各步骤之间不重叠、不遗漏，恰好完成这件事；3. 总方法数 = 各步方法数之积；4. 例如：南京→杭州9种，杭州→苏州6种，南京→苏州 = 9×6 = 54种 |
| 高频错因 | 把分步误用为分类；忘记步骤之间是"且"关系（都需要完成） |
| confidence | high |

## 补充说明

乘法原理本质是加法原理的特殊情况——每种上午方案都对应同样多的下午方案

## 不适用条件

1. 某步骤的方案数依赖于前一步的具体选择（非独立），需用条件计数或树状图分析。
2. 各步骤可独立完成任务（即任一步完成即可），应改用分类相加。
3. 步骤之间存在重复计数风险，需配合容斥原理核验。

## 反向触发

1. 当题目描述出现"或者""要么…要么…"等并列选择词时，应换用分类相加。
2. 当各步骤方案数不等或前后依赖时，应改用条件计数方法，并核验每步独立性。
3. 当题目涉及"任选一种方案即可完成"的语义时，应使用加法原理而非本方法。
