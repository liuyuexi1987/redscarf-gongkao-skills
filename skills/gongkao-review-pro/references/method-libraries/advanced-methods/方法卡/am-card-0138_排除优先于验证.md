# 方法卡：排除优先于验证

## 基本信息

| 字段 | 值 |
|------|-----|
| 方法名 | 排除优先于验证 |
| 适用题型 | 资料分析·选项判断题（混合增长率验证、综合分析等） |
| 触发场景 | 需要判断多个选项的对错，无法直接确认哪个选项正确，但存在明显极端或离预期最远的选项可代入排除 |
| 必要输入 | 完整的选项集合；至少一个可用于代入的已知条件（材料数据或计算中间结果） |
| 步骤逻辑 | 1. 从选项中挑出看起来最极端或离预期最远的选项 2. 将该选项代入已知条件进行验证 3. 若代入后推出矛盾（如数值明显超出合理范围、方向与材料相反）→ 该选项一定错 → 直接排除 4. 若代入后未发现矛盾，换下一个极端选项继续排除 5. 剩余未被排除的选项即为答案候选 |
| 验证动作 | 代入选项后必须确认存在明确矛盾（数值矛盾、方向矛盾或逻辑矛盾）才能排除；仅"无法确认对"不能作为排除依据 |
| 不适用条件 | 所有选项看起来都合理、无明显可排除项时不可强行使用；题目可直接代入确认正确答案时不需要排除法；选项间无明显区分度（如数值接近、方向相同）时不适用 |
| 高频错因 | 代入"看起来对"的选项验证后就直接选它，但实际无法确认100%正确；把"无法确认对"等同于"一定对"；按 ABCD 顺序验证第一个"合理"选项就停止；把排除法和确认法混用——排除法排除的是"一定错"，确认法确认的是"一定对"，二者不能互换 |
| confidence | high |
| 反向触发 | 1. 排除法仅剩一个候选选项但无法确认该选项一定正确时，不能直接选，应代入该选项做正向验证（确认法） 2. 代入后未发现矛盾但数值精度不足以判断对错时（如选项差距仅在小数点后），应改用精确计算而非继续排除 3. 连续排除两个选项后剩余两个选项无法区分时，排除法已到极限，应比较剩余两选项与已知条件的直接匹配程度 |
